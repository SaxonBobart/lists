## Structure and priorities

The existing structure is worth retaining: one Item model, one mutation/storage
boundary, shared calendar projection, and shared hierarchy/move sessions. The
main product gaps are inconsistent control ownership, narrow search, one Month
layout, difficult calendar import setup, and per-item text properties without a
shared list schema. Rebuilding the app or replacing storage would add risk.

## Product decisions for this work

- Search all nondeleted library content; retain local-only processing.
- One document property rail; keep Markdown body tools above its keyboard.
- Month Compact, Details and existing List, using supplied Apple references.
- Calendar copies continue receiving one-way updates with local-edit protection.
- Existing lists own shared typed fields and named List/Columns/Calendar/Table
  views. No duplicate content containers, formulas, relations or cloud service.
- Preserve unknown metadata, legacy properties and original attachment bytes.
