# UI and feature audit — 30 October 2026

Current app: canonical `dev`, initially `a62f6d6`. User screenshots define the
reported defects. This report separates source inspection, reproduced defects,
and runtime verification; a working button is not evidence that its outcome persisted.

## Structure and priorities

The existing structure is worth retaining: one Item model, one mutation/storage
boundary, shared calendar projection, and shared hierarchy/move sessions. The
main product gaps are inconsistent control ownership, narrow search, one Month
layout, difficult calendar import setup, and per-item text properties without a
shared list schema. Rebuilding the app or replacing storage would add risk.

## Product decisions for this work

- Search all nondeleted library content; retain local-only processing.
- One document property rail; keep Markdown body tools above its keyboard.
- Month Compact, Details and existing List, using supplied Apple references.
- Calendar copies continue receiving one-way updates with local-edit protection.
- Existing lists own shared typed fields and named List/Columns/Calendar/Table
  views. No duplicate content containers, formulas, relations or cloud service.
- Preserve unknown metadata, legacy properties and original attachment bytes.

## Remaining verification and limits

1. Real-iPhone Files/iCloud provider imports still require device verification;
   the host exposes simulators, not that physical phone.
2. The device tool stopped after its full-screen Toolbar coverage error and the
   unsupported keyboard-dismiss recovery. New calendar gestures, menu selection,
   database cell interactions and screen-to-screen tint transitions are not
   claimed to be driven/verified on-device. Hosted renders do not replace them.
3. Calendar permission/account behavior needs a real Apple Calendar source check;
   the import engine is covered using an injectable fixture source.
4. Compact/Details use full-month vertical pages, rather than Apple's continuously
   scrolling overview. Details shows up to two titles per day plus overflow and
   opens the day for full item access. Month List remains its previous layout.
5. Table targets item records. Standalone files remain in ordinary list/file views
   and whole-library search. Named views do not add formulas/relations/rollups,
   arbitrary column resizing or bulk table selection. Definition type changes
   require a new field, preserving old values instead of guessing conversions.
6. Existing recurrence notification delivery, physical haptics, full legacy
   snapshot reference set and iOS 26 runtime were not revalidated by this pass.
