## Verification

The repair handoff was reconciled before editing: the recovered aggregate had
787 passing tests and one compact Settings snapshot failure, and its processes
had exited. The empty original output file was not treated as success.

The Settings fixture now owns a fresh scene window, pins its appearance, mounts
before waiting and restores prior key-window/animation state afterward. Exact
image comparison remains in place. This avoids inheriting SnapshotTesting
key-window captures that resize and clear the shared window without restoring
its prior root/frame. The old wait wrapper delayed
before SnapshotTesting mounted the controller, leaving native toolbar rendering
unsettled. No comparison precision was relaxed. Independent fresh first captures matched
in visible-pixel comparisons in all three variants. The modern light/dark references were
unchanged. Only the compact reference was refreshed after independent visual
review: 4,157 pixels inside the native close-button edge, at most two RGB levels
apart, with unchanged text, glyph, control geometry and other content.
The approved reference is copied directly from native SnapshotTesting output,
preserving 16-bit channels; an 8-bit diagnostic re-encoding was discarded after
the aggregate correctly rejected it. A diagnostic second redraw varied slightly,
so it was not retained as a test
invariant or used to approve broad baseline changes. Temporary capture probes
and the unsuccessful image-format experiment were removed.

The final controlled aggregate passed **788 tests, 0 failed, 0 skipped** on
simulator `87800814-E5C1-437B-89A5-945B035C070D` / iOS 27.2. This run includes
the fresh-window fixture and reviewed native PNG. Earlier isolated successes
were not treated as a substitute for this aggregate. Static checks confirmed
project inclusion, valid app/privacy plists and test-plan JSON, working relative
documentation links, no app/test Habit references, and a clean diff check.
Independent review found no remaining code, lifecycle or documentation blocker.

Driven verification through Device Hub's desktop accessibility actions confirmed
Home, Search open/close, Settings, Task/Note/Event options, a sample PDF and the
paperclip browser. No unexpected visible layout defect or app exit was observed
in those flows. Ordinary-library and isolated sample-library hashes remained
unchanged. The command-wrapper and raw-driver input paths are documented
separately in AGENTS.md. The bundled AXe 1.8.0 physical-selector path also
verified current-build Search open/close on first attempts, with fresh screenshots
and hierarchies. This needs no proxy, new connector, installation or permission
change. A successful input response alone is never UI proof.

## Limits

This was an evidence-led local cleanup, not a proof that every remaining symbol
is necessary or that the app has no bugs. No physical-device, delivery,
distribution or end-to-end Calendar-account verification was performed here.
Those release gates remain explicit in the roadmap. No app library was erased,
no external service was contacted and no release or push was performed.
